# 取消任务后再次派单失败验收

日期: 2026-10-20. 时间为北京时间.

## 产生原因

原始记录确认, JOB-f9a24d0a10c4a9f2 在 16:26:35 进入执行, 16:26:38 被取消. 后续 JOB-4498b16b2ac698fb 在 16:26:56 立即失败, 提示 session 未就绪, 输入和输出 token 均为 0.

取消会关闭会话并删除引擎实例. 原逻辑在旧任务返回时无条件将会话改回 READY, 导致会话记录显示可用而实际没有引擎实例. 新任务复用该记录后立即失败. 同一会话 ID 重建后, 旧回合的延迟返回还可能覆盖新实例的运行状态. 本次失败发生在附件读取和模型执行之前.

## 解决方案

1. 旧任务返回时, 仅当仍是原会话实例, 状态仍为 BUSY 且引擎绑定存在, 才能恢复 READY. 已停止, 状态未知或同 ID 的替换实例不受旧回合影响.
2. 开始执行前检查会话归属, READY 状态及引擎绑定. 未就绪时返回失败, 保留原生命周期状态, 不先伪装成 BUSY.
3. 派单复用同时检查会话状态和实际绑定. 正在执行的会话不被另一任务强制停止. 启动失败包括已有活动会话错误均明确失败, 不再忽略错误后上报 READY.
4. 查询活跃会话返回受锁保护的副本, 避免外部读取与内部状态更新共用可变对象.
5. Codex 停止或断连时主动释放等待中的 RPC 和回合调用, 关闭的引擎不可复用. 补充本地验证发现的直接停止会话后等待不退出问题, 与取消清理属于同一生命周期链路.

## 测试要点

1. 取消后旧回合正常返回或错误返回, 会话均保持 STOPPED, 后续可重新创建并完成任务.
2. 旧回合返回前重建相同会话 ID 并运行新任务, 旧结果不将新实例的 BUSY 改成 READY.
3. STARTING, STOPPED, UNKNOWN, BUSY 以及 READY 但无引擎绑定均不能执行新任务, 拒绝后原状态不被篡改.
4. 普通回合错误但会话未停止时, 保留原有可复用行为. 既有运行时, 恢复管理及 daemon IPC 回归通过.
   Codex 额外覆盖等待 RPC 回复和等待回合完成两个阶段的主动停止, 重复停止和断连, 均立即返回生命周期错误.
5. 更新后检查 AEW 连接及用户会话启动方式, 通过本地真实模型进行停止后重建及文件读取验证. 用户原任务与飞书卡片不用于自动重放.

## 修改清单

- 工作站运行时: 任务开始条件, 会话收尾状态保护, 活跃会话快照和绑定检查.
- 工作站派单: 复用条件和启动失败处理.
- Codex 适配: 停止及断连释放等待调用, 已关闭的连接不接受新请求.
- 自动回归: 可控回合返回顺序, 取消后重建, 同 ID 替换实例及未就绪状态分支.
- 部署: 仅重建更新 AEW, 中心服务和后台无本次改动.

## 实际验证与部署

运行时及其恢复模块, daemon 和 Codex 适配测试通过, `git diff --check` 通过.

已部署版本通过独立本地 IPC 会话使用 gpt-5.6-luna 验证: 运行中的回合被停止后立即返回 Codex 会话已停止, 随后同一个会话 ID 重建成功. 下一任务用默认终端读取原 test.txt, 返回 `测试文件`, exitCode 0, 本地任务状态 SUCCESS. 测试结束已关闭诊断会话, 没有重放业务任务或发送飞书消息.
