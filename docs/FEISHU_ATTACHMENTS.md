# 飞书图片与文件

## 发送方式

1. 在机器人私聊中先发送图片或文件, 收到暂存提示后发送 `@test3 阅读附件并总结` 或 `/emp test3 描述图片中的问题`。
2. 回复原图片/文件消息, 在回复中写 `@test3 任务需求`。可以引用较早的附件, 不依赖临时暂存是否仍有效。
3. 在富文本消息里同时放入 `@test3 任务需求`、图片和文件, 一次派单。文件卡片可以放在文字下方, 同一消息内的位置不影响识别。

群聊中也按发送者分别暂存, 不会使用其他人的待派单附件。未提及机器人的群聊附件静默暂存, 是否能收到这类消息取决于飞书应用的消息订阅权限。可以回复附件并 @机器人, 然后写 `/emp test3 任务需求`。

`/files` 同时查看自己在当前会话的待派单附件和最近任务已使用的附件。历史从最近 100 条任务中查找, 最多显示 5 条含附件任务, 包含任务号、员工和文件名。成功派单后附件从暂存区移到任务记录, 所以没有待派单附件不代表以前没有发过附件。历史清单持久化, 重启后仍可查询, 不自动用于新任务; 再次使用请回复原附件消息派单。

`/clear files` 只清空待派单附件, 不删除历史任务记录。`/help` 等查询命令不消耗附件。成功创建任务后才消耗暂存附件, 下载/创建失败时保留以便重试。

## 限制与行为

- 每条任务最多 10 个附件, 单个最多 32 MiB, 合计最多 64 MiB。不接受空文件。
- 图片支持 PNG、JPEG、WebP、GIF。其它图片格式可作为普通文件发送。
- 临时待派单引用保留 15 分钟; 中心服务重启会清空尚未派单的暂存引用。可以重新发送附件或回复原附件消息恢复。
- 已创建任务的附件清单保存在数据库, 内容持久保存在服务端数据卷的 `artifacts/inputs`。工作站下载不依赖飞书附件短期地址。
- 图片向 Cursor 使用 ACP 原生 image 内容块, 向 Codex 使用原生 localImage 输入。其它文件保留完整字节, 以本地路径交给引擎原有文件工具读取。PDF 等文档按引擎工具能力处理, 不新增平台专用解析器或将正文内联作为替代。
- 工作站文件位于任务工作区的 `.aie-inputs/<任务散列>/`。文件不会被自动执行或解压。附件属于用户提供的输入内容。
- 飞书机器人需要读取被引用消息和消息资源的权限。权限不足、资源过期、大小超限或校验失败时会提示失败, 不会静默丢弃附件后执行任务。

## 实现结构

- `gen/jobinput`: 服务端与 AEW 共用附件清单、校验和下载签名协议。
- `server/internal/feishu/attachments.go`: 提取 `content` / `content_v2` 行资源及同级 `files` 数组, 兼容语言包装并按消息/资源键去重; 按发送者和会话暂存、引用消息解析、通过官方 SDK 下载。
- `server/internal/taskconversation/attachments.go`: 按当前发送者及会话查询已持久化的任务附件, 与待派单暂存分离。
- `server/internal/jobinput`: 按 SHA256 持久保存内容。任务创建时原子写入附件清单, 避免调度先于附件就绪。
- `jobs.input_attachments`: 第 32 号数据库迁移, 保存清单; 普通任务创建 API 不接受用户自行填写散列引用。
- `server/internal/api/job_input_handlers.go`: 工作站证书和签名鉴权, 同时校验任务分配与清单归属。
- `workstation/internal/artifactlocal/downloader.go`: 带身份签名下载、禁止重定向、校验大小和 SHA256, 原子写入工作区。
- AEW daemon 将文件路径追加到本轮任务, 并通过本轮上下文携带原生图片输入; 下一轮任务不自动复用图片内容块。

附件清单通过已有 START_JOB 的 `payload_json.input_attachments` 下发, 与已有结构化 payload 并存。中心服务和 AEW 需同时升级。

## 验收要点

1. 图片和中文文件名分别先发后派单, 能读取真实附件字节; 同条富文本的图片、文字及底部 TXT 文件均进入任务, `content_v2` 重复图片不重复下载; 回复原文件也能派单。
2. 不同发送者、不同会话的附件相互隔离; 帮助查询不消耗附件; 清空只影响自己的暂存; 成功派单后暂存清空。
3. 飞书资源权限错误、下载失败、空文件、超限、损坏响应均有明确反馈, 不执行缺失附件的任务。
4. 工作站只能下载分配给自己的任务且列在清单里的文件; 伪造签名、跨任务散列、跨工作站访问被拒绝。
5. 本地重复下载可覆盖自己的旧文件, 中文名正常, 文件名不能逃出工作区, 下载内容与服务端 SHA256 一致。
6. Cursor session/prompt 确实收到图片字节, Codex turn/start 确实收到 localImage; 后续无附件任务不残留原生图片输入。
7. 迁移完成后中心服务正常启动, AEW 重新上线, 普通文本派单与既有命令仍可使用。
