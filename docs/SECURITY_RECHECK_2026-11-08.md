# 外网部署安全复查与修复（2026-11-08）

已将 `codex/pve-software-management`（`ef9e45d`，前序 `7f855ea`）快进合并到本地 `main`。以下编号沿用此前的 **13 项风险**，与分支中 2026-10-25 文档的 15 项编号不同。

本次结论针对仓库代码、默认部署配置和本地验证环境。没有推送远程、升级线上镜像、修改线上数据库密码或迁移线上密钥。

## 13 项复查结果

| 原编号 | 风险 | 合并后复查及最终处理 |
| --- | --- | --- |
| 1 | 数据库对公网发布、固定数据库密码 | 分支已删除 PostgreSQL 端口发布，Compose 要求提供密码，production 启动拒绝弱密码。已验证 Compose 渲染结果：数据库无宿主机端口。 |
| 2 | 初始化接口被抢占、创建首个管理员 | 分支已要求部署初始化口令，数据库事务与 advisory lock 保证只创建一次，并保存永久初始化标记。新增无口令/错误口令拒绝测试；真实 PostgreSQL 中 8 个并发初始化只有 1 个成功。 |
| 3 | 固定 Secrets/备份加密密钥 | 分支已移除固定后备密钥；文件 Vault 缺少稳定密钥或不能解密旧数据时拒绝启动。production 要求三组独立密钥，提供离线迁移工具。新增生产缺失/弱密钥、复用密钥、弱数据库密码拒绝测试。 |
| 4 | HTTP 注册和管理接口直接暴露 | 分支已将 HTTP/admin/gRPC 的宿主机端口默认绑定回环；公开入口可用 Caddy 自动 HTTPS；远程注册强制 HTTPS。已验证 Compose 只有 gateway 默认发布 80/443，其他端口回环。 |
| 5 | MCP 绕过 REST 权限或员工授权范围 | 分支已检查当前角色、全局写/删除权限。仍存在技能检查工具泄露范围外元数据的问题：本次给 `check_skill`、`check_local_skills`、`check_workflow_skills` 补齐范围检查，批量检查的计数也只计算授权技能。权限与范围回归测试通过。 |
| 6 | 工作站伪造其他节点、员工或任务的事件 | 分支已校验事件与证书、job/employee/session/workspace 的归属。本次修正身份字段解析，既拒绝冲突 ID，也允许合法请示选项数组与进度数字；越权事件导致连接被拒绝，不能进入回调。真实 mTLS 和资源归属回归测试通过。 |
| 7 | 撤销角色后旧会话继续有效；吊销证书后旧长连接继续工作 | Web 会话的角色刷新和凭据版本校验已由分支修复。工作站连接仍有缺口：本次每次 RPC、上行帧、下行命令及 Resume 都检查实际对端证书；闲置连接每秒复核；取消连接能中断等待接收。测试覆盖旧连接 Ping、下行命令、闲置连接吊销、主动断开，以及会话撤权。 |
| 8 | SSE 跨用户泄露任务/员工元数据 | 分支已按资源权限和归属过滤历史及实时事件，刷新会话并限制连接数。本次进一步在资源服务缺失时直接拒绝；修复事件发布与取消订阅并发导致的关闭 channel 写入崩溃。越权事件过滤和并发回归通过。 |
| 9 | 自动化 Webhook 信任伪造 XFF、签名可重放 | **合并后仍存在，已修复。** 来源仅使用可信代理适配层解析的 IP；HMAC 请求按自动化 ID、原始时间戳和规范化签名计算一次性键，未签名的幂等请求头不能绕过；PostgreSQL 原子认领跨进程/重启生效，存储失败拒绝执行。Bearer 请求必须提供幂等键。重复请求返回 409；过期认领定期清理。代理链、伪造 IP、重放、并发和持久化测试通过。 |
| 10 | 请求体、超时和并发缺乏约束导致 DoS | 分支已加入分路由请求体限制、请求头/读取/空闲超时、普通与大上传并发上限、SSE 连接及写入限制。本次增加普通响应写入超时，并让 Webhook 超过 1 MiB 时返回 413，避免静默截断。边界测试通过。 |
| 11 | 审计仅存内存且无限增长 | 分支已将 production 审计接入 PostgreSQL并限制查询数量；真实数据库验证重新建立连接后仍能读取审计。本次也限制开发内存审计的保留数量（最多 10,000 条，达到上限时批量淘汰最旧记录）。 |
| 12 | SFTP 不校验主机密钥，可能被中间人截获备份 | 分支已要求可信 SHA256 主机指纹并进行恒定时间比较；缺失或不匹配拒绝连接。复查确认备份连接不再使用 `InsecureIgnoreHostKey`。 |
| 13 | Go/前端依赖存在已知漏洞 | **合并后仍存在，已修复。** Go 工具链、Docker 构建与 CI 统一为 1.27.3；升级 gRPC 1.83.2、pgx 5.9.2、x/net 0.62.0、x/crypto 修复提交、WebSocket、压缩与 protobuf 依赖；原 SMB 库无修复版，切换到已维护的 cloudsoda 分支。前端升级 Vite/source-map-js，并覆盖 Monaco 的 DOMPurify 至安全版本。服务端、工作站扫描均无告警，npm audit 为 0。CI 加入持续扫描。 |

额外修复：飞书管理绑定接口从员工记录取得 `OwnerUserID` 并保存，避免缺少归属的合法绑定被运行时拒绝；MCP 调度在员工服务缺失时拒绝凭据注入。旧测试中的自动绑定、无授权事件、无初始化口令、无二次认证上传等假设已更新，安全约束保持生效。

## 升级部署时必须应用的配置

1. 参考 [现有安全升级说明](SECURITY_HARDENING_2026-10-25.md) 备份并迁移旧 Vault/TOTP/备份密钥；不能仅替换环境变量，否则旧密文无法解密。现有 PostgreSQL 实际密码也需要与新连接配置同步。
2. 设置 `AIE_ENV=production`、三组独立随机密钥、强数据库密码、可信 HTTPS 公网地址；执行数据库迁移，并重建/更新服务端与管理页面镜像。
3. 重新登录并完成管理员 MFA；重新保存历史飞书绑定；为 SFTP 备份补充通过可信渠道核对的主机指纹。
4. 按实际网络配置可信代理 CIDR。远程工作站需要显式开放 mTLS 的 gRPC 入口，并限制防火墙来源。不要把回环的 HTTP/admin 端口直接转发到公网。
5. 自动化 Bearer 调用加入 `X-Idempotency-Key`（最多 256 字符）；HMAC 同一签名只允许执行一次，重试返回 409。新的独立事件使用新的签名时间戳；RFC3339 支持小数秒。防重放存储不可用时请求不会派发。

以上 13 项在代码与默认配置中的原始问题均已处理；上线后的安全性仍取决于实际应用这些配置、数据迁移和网络入口限制。真实 SMB/SFTP 服务、真实飞书账号及线上网络环境未在本次本地验证中连接。
