# PVE 与软件管理

本功能提供三条完整路径：PVE 资源管理与 Linux 主机接入、软件发布和部署、定期更新与维护。管理员入口为「PVE 管理」「软件管理」「部署任务」。外部 Linux 主机也可登记后部署软件，无须绑定 PVE。

## 部署准备

- 应用升级前，按现有流程运行 migrations；新增迁移为 `000034_infrastructure.sql`，不会在服务器启动时自动修改 schema。
- PostgreSQL 保存连接、主机、软件、发布、安装记录、策略和任务。无数据库开发模式使用内存存储，重启后不保留这些记录。
- `AIE_SOFTWARE_DIR` 为安装包目录，默认在 `AIE_ARTIFACT_DIR/software` 下。默认路径已在现有制品持久化和备份范围内；自定义目录时须自行持久化并纳入备份。
- 继续使用保险箱的 `AIE_SECRET_DIR` 和 `AIE_SECRET_MASTER_KEY`。恢复时同时恢复数据库、软件包和保险箱，不要只恢复其中一项。
- 已更新 Nginx WebSocket 转发与 514 MiB 上传限制，反向代理和 Vite 开发代理需要随本次修改一并更新。平台限制单个软件包 512 MiB、提取后的程序 256 MiB。
- 本地开发时可用 `AIE_DEV_API_TARGET` 覆盖 Vite 的后端地址，默认 `http://127.0.0.1:8080`。
- 部署执行器需要直连 PVE HTTPS API，以及虚拟机的 SSH 端口；虚拟机需要访问 Control Plane HTTP 和 mTLS gRPC 入口。PVE 可达不代表客体 SSH 可达。

## PVE 与主机接入

1. 在 PVE 创建专用 API 用户及 Token，并授予实际使用的节点、资源池、模板、存储与虚拟机权限。列表读取、克隆、资源配置、磁盘扩容、Cloud-init、Guest Agent、启动关机分别需要相应权限；以所用 PVE 版本 API 权限说明为准。
2. 在「PVE 管理 → 管理凭证」保存 PVE Token，格式为 `user@realm!tokenid=secret`。系统以 `infra.pve.*` 名称加密保存。也支持直接引用保险箱中以 `user@realm!tokenid` 命名的已有凭证，值可为 Secret 或完整的 `user@realm!tokenid=secret`；下拉框只返回名称、类型和引用 ID。不会复用飞书或 TOTP 等系统凭证。
3. 添加 PVE HTTPS 地址并关联 Token。私有证书需要填写可信 CA 的 PEM；程序不会关闭 TLS 验证。同步后显示节点及 QEMU 虚拟机，LXC 容器不在本版部署范围。
4. 从现有 Linux Cloud-init 模板克隆，设置 VMID、节点、CPU、内存、存储、网桥、网络、用户和公钥。磁盘可选择扩容，根磁盘设备须与模板一致，例如 `scsi0`；磁盘大小为 0 时沿用模板。模板必须准备 Cloud-init 驱动盘，并在首次启动重新生成客体 SSH 主机密钥。
5. 模板内安装并启用 QEMU Guest Agent 后，可在详情读取 IP；没有 Agent 时手动填写 SSH 地址。创建时可选择后续安装的软件。虚拟机创建成功后，任务会等待管理员填写 SSH 配置并核对主机指纹，再继续安装。
6. 在主机详情配置 SSH 用户、端口、保险箱中的密码或私钥。先保存地址并探测公开指纹，再通过 PVE 控制台等可信渠道核对并保存。探测阶段不向未验证主机发送认证凭证。
7. 「SSH 登录」打开交互式 PTY，支持终端缩放与 Ctrl+C。连接使用 30 秒一次性票据，同源校验，会话最长 30 分钟；管理员登录令牌和私钥不会出现在 WebSocket URL 中。多后台实例部署时，票据创建和 WebSocket 连接需要路由到同一实例。

PVE 资源每分钟自动同步，也可手动同步。虚拟机从一个节点迁移到另一个节点时，按「连接 ID + VMID」保留 SSH、工作站和安装关联。PVE 删除资源后，平台保留历史并标记 `missing`，不会删除客体或自动清理磁盘。

## 软件发布与安装

软件定义保存安装方案和更新源，发布保存不可覆盖的版本及平台，安装记录关联主机与发布。首次提供 aew 和 Codex CLI 两种内置方案，也可添加独立程序。

- 本地上传：提供版本、系统、架构、包格式，平台保存原包并计算 SHA256。支持原始程序、tar.gz、zip，可下载回本地。更新链接允许为空。
- 在线包：提供 HTTPS 下载地址与 SHA256。首次部署或下载时缓存，之后使用缓存。每次部署重新校验缓存摘要。
- 归档：只读取一个普通程序文件，不向磁盘释放归档中的路径、目录或软链接。若自动匹配程序名不成功，填写包内路径，例如 `bin/codex`。
- 安装方案：当前面向可独立运行的 Linux 程序，平台不会把任意安装文件猜成通用安装器。额外的系统运行库、Git、运行环境等请在模板中准备。Windows/macOS 软件包可保存和下载，远程安装目标目前为 Linux amd64/arm64。
- 安装目录：`~/.local/share/aie-software/<software>/<release>/program`，入口在 `~/.local/bin/`。不会覆盖入口处已有的普通文件。保留发布文件以支持切换版本，不删除项目数据或软件账号配置。
- 安装检查：按配置的版本检测参数执行程序，可额外指定安装后健康检查命令。页面同时显示登记版本和实际输出，避免把文件标签当作实测版本。

aew 可由本仓库交叉编译后上传，例如在 workstation 模块中以 `GOOS=linux GOARCH=amd64` 构建 `./cmd/aew`。首次部署填写客体可访问的 Control Plane HTTP 地址，执行器即时生成短期单次 Enrollment Token，注册新的工作站身份，安装常驻服务并检查连通和在线心跳。注册凭证不会写入模板或部署参数。

aew 与 Codex 以同一个 SSH 用户运行，`AIE_DATA_DIR=$HOME/.aie`、PATH 包含 `~/.local/bin`。非 root 用户需具备免密 sudo，用于启用 linger 和启动 systemd 用户管理器；aew 本身仍以该普通用户运行。root SSH 用户使用系统级 systemd 服务。

Codex 软件安装与账号认证分开记录。可在详情选择保险箱 API Key 登录；或在 SSH 终端运行 `codex login --device-auth`，完成浏览器认证后点击重新探测。设备码是否可用取决于账号/工作区设置。参见 [官方认证文档](https://learn.chatgpt.com/docs/auth)。本功能不会自动共享其他人的账号认证文件。

## 更新源与自动维护

「检查更新」支持以下来源：

- 无更新源：使用手动上传的版本；不会报缺少链接，也不会访问外网。
- HTTPS JSON 清单：适合内部发布系统和 aew 自建发布源。
- GitHub Release：读取稳定版发布与指定名称的安装包。Codex 默认读取官方 `openai/codex` 最新发布，默认 Linux amd64，可改为 arm64。名称中的 `{arch}` 对应 `x86_64` 或 `aarch64`。上游没有提供 digest 时，先缓存并计算摘要再登记发布。

版本清单示例（摘要替换为真实安装包的 64 位 SHA256）：

```json
{
  "releases": [
    {
      "version": "1.2.0",
      "os": "linux",
      "arch": "amd64",
      "format": "binary",
      "url": "https://packages.example.com/aew-linux-amd64",
      "sha256": "<真实安装包的 SHA256>",
      "notes": "本次发布说明"
    }
  ]
}
```

源凭证只发给同源请求；跨域安装包和跳转不会携带更新源的 Bearer Token。若私有安装包位于另一域名，请将其转存到同源下载服务，或在平台手动上传。

在主机的已安装软件中配置策略：启用检查、检查间隔、是否自动部署、目标版本、维护窗口与时区。两个窗口端点相同时表示全天，跨午夜窗口也支持。发现上游版本按配置周期执行，维护窗口每分钟独立评估。没有在线源时，平台里手动上传的新版本也可被自动部署。

自动维护只更新已有安装，不执行首次安装或注册；未锁定目标时优先选择更高的稳定版本，预发布版本需明确锁定或手动部署。工作站有已分配、启动中、运行中或状态未知的业务任务时等待，新任务暂不分配到维护主机。软件升级完成后恢复调度。

每台主机同时只有一个基础设施任务。安装检查失败时尝试恢复入口；aew 服务启动失败时尝试恢复上一程序并重新安装、启动其服务。平台保留当前与上一成功发布，提供手动回滚。任意软件的数据格式变更和依赖迁移不在二进制切换的回滚范围内，应在健康检查中验证适用性。

同一版本的自动部署失败后暂停重复尝试，管理员核实日志后可重试原任务，或重新开启策略。排队/等待中的任务可以取消，取消保留已经创建的虚拟机和文件。执行中任务不提供强制杀进程操作。

## 任务可靠性与权限

- 任务先落库，再由执行器领取。PostgreSQL 使用 `FOR UPDATE SKIP LOCKED`、主机活动任务唯一索引和幂等键，避免多进程重复部署。
- 执行器每 20 秒续租，租约两分钟。租约过期标记 `INTERRUPTED`，不自动重放远端副作用。单次执行最长 30 分钟。失败和中断可显式重试。
- 若克隆请求已在 PVE 成功、但平台未能保存成功标记，重试会拒绝接管现有 VMID。请先在 PVE 核实，随后同步并从已有主机详情继续部署，避免误覆盖资源。
- 新权限为 `infra.read/manage/deploy/console/credential`，所有入口要求 `ALL` 范围。默认只给 ADMIN 和 SUPER_ADMIN，不扩展普通用户的本人范围权限。
- 创建/部署/回滚、SSH、凭证写入和明文查看、策略保存要求二次认证。开启自动部署还要求 `infra.deploy`，不能仅凭管理策略权限获得远程执行能力。
- 凭证列表脱敏，明文查看单独审计；UI 30 秒后隐藏已查看内容。只允许访问基础设施专用凭证和以 PVE Token ID 命名的已有 PVE 凭证，不能借新接口读取 TOTP 或其他系统凭证。已有 PVE 凭证不能用于 SSH 或软件下载。

## 验收路径

1. 正确/错误 PVE Token 和 CA；查看节点与虚拟机，节点迁移后检查关联不丢失。
2. 克隆 Linux 模板，确认 CPU/内存/网络/磁盘扩容；检查 VMID 冲突、权限不足和部分成功后的处理。
3. 保存 SSH 凭证，核对指纹，测试错误指纹拒绝连接，打开 PTY 并执行交互命令。
4. 空更新源上传 aew，下载核对原包，安装并注册；检查主机详情到工作站的跳转与在线状态。
5. 部署 Codex，分别验证未登录、API Key 登录和设备码登录后的状态。
6. 上传新版本，分别测试只提示、窗口内自动部署、跨午夜窗口、版本锁定、工作站忙时等待和取消。
7. 注入校验失败、健康检查失败、源不可达和执行器中断，确认不会错误标为成功、不会无限自动重试；验证上一发布回滚。

自动测试使用模拟 PVE HTTPS API、下载源和 SSH 执行器；真实 PVE 模板、网络、systemd 与账号登录需在接入实际服务器后完成上述联调验收。
